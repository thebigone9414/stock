# 자동매매 구현 지시서 v1 - 코스피200 ETF 11패턴 + 개별주식 일일 규칙

**2026-10-09 · 대상: 클로드 코드 · 목적: 두 규칙을 시간대별 점검 방식의 자동매매로 구현하고, 매일 최종 종가 확정 후 다음날 주문 계획을 텔레그램으로 보고**

---

## 0. 원칙

1. **신호 계산은 기존 코드가 단일 진실이다.** 규칙을 다시 구현하지 말고 엔진 패키지 `engine_v3/` (별도 zip, 레포에 그대로 풀어 넣는다) 를 import해서 쓴다. 백테스트와 운용이 같은 함수를 써야 성적이 비교된다. 상세는 `engine_v3/README.md`.
   - 코스피200 ETF: `daily_v3.add_bar(날짜,시,고,저,종)` 로 지수 일봉 추가 → `daily_v3.judge(dep=ETF 몫 평가자산)` 가 보유 점검·오늘 신호·손절선을 dict 로 반환 (내부: `lib.py` 지표, `hunt.py` 트리거·상태, `vehicle.py` 패턴 조립, `PAT` 사전)
   - 개별주식: `stock_lib.append_bars(당일 344행)` 로 종목 일봉 추가·패널 재생성 → `stock_rules.judge(P, capital=종목 몫 평가자산)` 가 보유 점검·신호·매수 대상(금액·수량)을 반환 (내부: `stock_lib.patterns_for` 패턴 15개, `stock_rules.CARD/PRIO`, `today_signals`, `check_positions`)
   - 사람이 볼 때는 CLI `daily_v3.py`, `daily_stock.py` (같은 함수를 출력만 붙여 실행)
   - 규칙 문서: `engine_v3/docs/새규칙_v3_규칙집.md`(ETF, 11패턴), `engine_v3/docs/개별주식_매매기법_v1.md`(종목)
   - 기본 데이터: `engine_v3/k200.csv`(지수 2000~2026-10-08), `engine_v3/stockdata/ohlcv.csv.gz`(344종목 2016-10-11~2026-10-08, 수정주가). 자동매매는 여기에 매일 1행씩 붙인다
2. **판정은 하루 한 번, KRX 정규장 종가 확정 후.** 장중에는 손절 감시와 예약된 주문 실행만 한다. 장중 가격으로 새 판정을 하지 않는다.
3. **모든 가격 판정은 KRX 정규장 기준이다.** ETF 규칙은 코스피200 **지수** 시고저종(ETF 가격이 아님), 종목 규칙은 종목의 KRX 정규장 시고저종·거래량. NXT(대체거래소) 체결가는 판정에 쓰지 않는다. 데이터 확정 작업만 NXT 종료(20:00) 뒤에 돌린다.
4. **주문은 두 종류뿐이다.** 매수 = 장 마감 동시호가 시장가(15:20~15:30 접수, 15:30 체결). 매도 = 장전 동시호가 시장가(08:30~09:00 접수, 09:00 체결) 또는 손절 시 즉시 시장가.
5. **두 규칙은 자본을 나눠 쓰고 섞지 않는다.** 한 쪽 현금을 다른 쪽이 쓰지 않는다.
6. **모르면 멈춘다.** 데이터 날짜 불일치, API 오류, 잔고 대사 불일치가 나면 그날 주문을 내지 않고 텔레그램으로 알린다.

## 2. 규칙 A - 코스피200 ETF 11패턴 (운용 수단 KODEX 레버리지, 숏은 KODEX 인버스)

### 2-1. 시점 표

| 단계 | 시점 | 기준 | 행동 |
|---|---|---|---|
| 판단 | 매일 20:10 (정규장 종가 확정 후) | 코스피200 지수 당일 시고저종을 `k200.csv`에 추가 → `daily_v3.py` 로직 실행 | 신호 패턴 목록, 보유분 청산 여부, 손절선 산출 |
| 진입 | 신호 **다음 거래일 15:21** | 15:20~15:30 장 마감 동시호가 | KODEX 레버리지 시장가 매수 (숏 #11은 KODEX 인버스 매수). 금액 = ETF 몫 평가자산 x 20% (숏 40%) |
| 익절 = 청산 | 청산 조건이 종가에 성립한 **다음 거래일 08:50** | 패턴별 청산 조건 (아래 표) | 장전 동시호가 시장가 매도 → 09:00 시가 체결. 목표가 없음, 기한 없음, 추적손절 없음 |
| 손절 | 매수 다음 거래일부터, 장중 체크포인트 (09:05 10:00 11:00 12:00 13:00 14:00 15:00 15:15) | 코스피200 지수 현재가 <= 손절선 (롱), >= 손절선 (숏) | 즉시 시장가 매도 (인버스는 매도). 손절선 = 신호일 지수 종가 - min(5 x ATR20, 종가의 10%). 신호일 값으로 고정 |
| 충돌 | 같은 날 청산 조건과 손절 | | 손절(장중)이 먼저. 손절 뒤 그 패턴의 청산 신호는 무시 |

ETF 가격 기준 손절선은 보고용 근사치로만 표시한다: 매수가 x (1 - 2 x 손절폭). 레버리지 ETF는 일간 복리라 지수 손절선과 정확히 대응하지 않으므로 판정은 반드시 지수로 한다.

손절을 장중 터치로 하면 24년 CAGR 15.9% / MDD -31.8%, 종가에만 판정해도 16.9% / -30.9%입니다. ETF 규칙은 손절이 거래의 3%라 시간대 점검으로 충분합니다.

## 3. 규칙 B - 개별주식 일일 규칙 (코스피200 + 코스닥150 구성종목 344개)

| 진입 | 신호 **다음 거래일 15:21** | 장 마감 동시호가 | 시장가 매수, 금액 = 종목 몫 평가자산 x 10%. 빈 자리 수만큼 6개월 수익률 상위부터 |
| 익절 = 청산 | 종가 < 종목 62일선인 **다음 거래일 08:50** | 패턴 무관, 62일선 하나 | 장전 동시호가 시장가 매도 → 09:00 시가 체결. 목표가·기한·추적손절·부분 익절 없음 |
| 손절 | 매수 다음 거래일부터, 장중 체크포인트 (09:05 10:00 11:00 12:00 13:00 14:00 15:00 15:15) | 종목 현재가 <= 손절가 | 즉시 시장가 매도. 손절가 = 신호일 종가 - 2 x ATR20 (상한 없음, 신호일 값 고정) |
| 재진입 | 청산 뒤 새 신호 | | 같은 종목이라도 새 신호면 새 거래 |
| 추가 매수 / 물타기 / 본전 손절 / 피라미딩 | | | 전부 없음 (검증에서 손해) |

### 3-2. 진입 카드 (`stock_rules.CARD`의 15개 패턴 → 11개 카드. 조건은 `stock_lib.patterns_for` 가 단일 진실)

A1 MACD 골든 + 62상승 · A2 RSI50 상향 + 히스토 음수 + 62상승 · A3 5/21 골든 + 5일 수익 양수 + 62상승 · A4 62선 상향돌파 + RSI 40~60 + 62상승 · B1 52주 신고가 + (정배열 또는 거래량 1.5배) · B2 20일 고가 돌파 (+ 거래량 1.5배) · B3 55일 고가 돌파 · B4 20일 박스(폭 20% 이내) 상단 돌파 + 거래량 1.5배 · C 감천 격자 F0.309/0.382/0.5 상향돌파 + 62상승 · D 쿨라매기 (60일 +20% 선행, 15일 박스 돌파, 거래량 1.3배) · E RSI 30 상향 + 62상승

한 종목에 여러 카드가 동시에 뜨면 1건으로 본다 (귀속은 `stock_rules.PRIO` 순서).

### 3-3. 손절 감시 간격의 영향 (백테스트)

종목 규칙은 손절이 거래의 35%라 감시 간격이 성적에 영향을 줍니다. 장중 터치 기준 CAGR 27.0% / MDD -44.0% / 최악 연 -7.3%, 종가에만 판정하면 25.5% / -50.7% / -26.1%. 시간대 점검은 그 사이입니다. **증권사 API가 STOP(조건부) 주문을 지원하면 매수 다음날 장 시작 전에 손절가로 STOP 시장가 주문을 걸어 두는 것을 1순위로 한다.** 안 되면 체크포인트 간격을 30분으로 줄인다.

## 6. 주문 실행 상세

- 매수: 15:21 시장가 1회. 체결 수량이 계획의 90% 미만이면 텔레그램 경고 (추가 주문 안 함).
- 매도: 08:50 시장가 1회. 미체결(거래정지 등)이면 다음 거래 가능일 08:50에 재시도, 상태는 "매도 대기".
- 손절: 체크포인트에서 조건 충족 즉시 시장가. 같은 종목 중복 주문 금지.
- 수량: 매수 금액 / 전일 종가 → 내림. 호가 단위는 시장가라 무관.
- 멱등성: 주문 키 = 날짜 + 종목 + 사유. 같은 키가 이미 체결·접수 상태면 다시 내지 않는다. 프로세스가 재시작돼도 중복 주문이 나지 않게 상태를 파일에 먼저 기록하고 주문한다.
- 대사: 08:20과 20:10에 증권사 보유 내역과 `positions_v3.csv` / `positions_stock.csv` 를 비교. 다르면 자동매매 중지 + 텔레그램.
- 한도: 하루 매수 주문 최대 15건, 매도 최대 15건. 초과 시 중지 + 알림.
- 수수료·세금은 기록만 한다 (규칙에 반영 없음).

## 9. 안전장치

1. **dry-run 모드**로 2주: 주문을 내지 않고 계획·보고만 보낸다. 백테스트 `11패턴_매매시점_전체목록.xlsx` / `개별주식_v1_매매목록.xlsx`의 최근 거래와 재현 결과를 대조해 신호가 일치하는지 확인한 뒤 실주문으로 전환.
2. 데이터 날짜가 오늘이 아니거나 두 데이터(지수·종목) 날짜가 다르면 주문 계획을 만들지 않는다.
3. API 오류는 3회 재시도, 실패하면 그 작업만 건너뛰고 알린다. 매도 실패는 다음 체크포인트에서 재시도.
4. 중지 스위치: `STOP` 파일이 있으면 매수는 내지 않고 매도·손절만 수행.
5. 총 평가자산이 전고점 대비 -35%(ETF 규칙) / -45%(종목 규칙)에 닿으면 그 규칙의 신규 매수를 멈추고 알린다 (백테스트 최대 낙폭 수준. 재개는 수동).
6. 로그는 날짜별 파일로 남기고 텔레그램에는 요약만.

## 12. 구현 착수 전 질문에 대한 답 (2026-10-09)

1. **엔진 모듈과 참조 문서가 레포에 없음** → `engine_v3.zip` 을 레포 루트에 풀어 `engine_v3/` 로 둔다 (코드, 기본 데이터, 문서, 상태 파일 전부 포함). 경로는 폴더 기준이라 그대로 import 하면 된다. 규칙집만 보고 새로 구현하지 않는다.
2. **기존 S2/S3/S4/S5 전략 코드** (ma_store, canslim_store, sepa_store, momentum_store, intraday_monitor, trade_decision, morning_trade) → `legacy/` 로 이동하고 스케줄러·진입점에서 뗀다. AUTO_TRADE_ENABLED 류 플래그는 새 시스템에서 다시 정의한다. 삭제는 안 하고, 새 코드가 옛 상태 파일을 읽지 않게 파일 이름을 분리한다.
3. **증권사 API 확인 순서** (한국투자증권 Open API 기준)
   - 1순위 코스피200 **지수** 시고저종 일봉과 현재가: 업종(지수) 시세 API 에서 업종코드 2001(코스피200)로 받을 수 있는지 확인. 일봉은 20:10 수집용, 현재가는 체크포인트 손절 감시용. 안 되면 pykrx 등 KRX 소스로 별도 수집하되 "정규장 종가"인지 확인.
   - 2순위 장전·장마감 동시호가: 별도 플래그 없이 **일반 시장가 주문**을 08:30~09:00, 15:20~15:30 에 넣으면 동시호가에 참여한다. "장전 시간외", "장후 시간외", "시간외 단일가" 구분은 쓰지 않는다 (전일 종가·NXT 가격 체결이라 규칙과 다름). API 주문 접수 시작 시각(08:30 인지)을 확인한다.
   - 3순위 STOP(손절 감시) 주문: Open API 에 자동감시(스탑로스) 주문이 있는지 확인. 없는 것으로 알고 있으며, 없으면 종목 손절은 체크포인트 간격을 30분으로 줄여 감시한다. ETF 는 지수 기준 손절이라 어차피 체크포인트 감시.
