## 1. 원칙

1. **신호 계산은 `engine_v3/`가 단일 진실이다.** 모듈 A는 `daily_v3.add_bar()` → `daily_v3.judge()`, 모듈 B는 `stock_lib.append_bars()` → `mom_lib.judge()`. 규칙을 다시 구현하지 않는다. 상세는 `engine_v3/README.md`.
2. **판정은 하루 한 번 20:10, KRX 정규장 종가 확정 후.** 예외 없음.
3. **모든 가격 판정은 KRX 정규장 기준.** 모듈 A는 코스피200 **지수** 시고저종, 모듈 B는 종목 정규장 종가·거래량. NXT 체결가는 쓰지 않는다. 데이터 확정은 NXT 종료(20:00) 뒤.
4. **주문은 두 시각뿐이다.** 매수·교체 = 15:21 장 마감 동시호가 시장가. 매도 = 08:50 장전 동시호가 시장가. 장중 감시 없음.
5. **두 모듈은 장부가 분리된 별개의 계좌처럼 다룬다.** 한 모듈의 현금을 다른 모듈이 쓰지 않는다.
6. **모르면 멈춘다.** 데이터 날짜 불일치, API 오류, 대사 불일치 → 그날 주문 없음 + 텔레그램.

## 2. 자본과 장부 (별도 관리)

| | 모듈 A (ETF 11패턴) | 모듈 B (월말 모멘텀) |
|---|---|---|
| 시작 자본 (`config.yaml`) | 25,000,000원 | 10,000,000원 |
| 건당 금액 | 모듈 평가자산 x 20% (시작 시 500만원). 숏 #11은 x 40% (인버스) | 모듈 평가자산 / 10 (시작 시 100만원) |
| 동시 보유 | 5건 (숏 포함) | 10종목 |
| 수량 | floor(건당 금액 / 전일 종가), 최소 1주 | floor(종목당 금액 / 종가). 1주 가격이 종목당 금액의 100~150%면 1주, 150% 초과면 건너뛰고 다음 순위 종목으로 대체 (`mom_lib.judge` 가 처리) |
| 현금 부족 | 남은 현금이 건당 금액의 절반 이상이면 남은 금액으로, 아니면 건너뜀 | 같음 |

장부: 모듈마다 `ledger_A.csv`, `ledger_B.csv` (날짜, 현금, 보유 평가액, 평가자산, 보유 수, 당일 손익). 매일 20:10 기록.
대사: 매일 08:20, 20:10에 `A현금 + B현금 + 미배정 현금 = 증권사 예수금`, `A보유 + B보유 = 증권사 보유`를 확인. 다르면 자동매매 중지 + 텔레그램.
입출금: 미배정 현금으로만 처리. 모듈 자본 증액·감액은 `config.yaml` 수정과 수동 명령으로만 한다 (자동 재배분 없음).

## 3. 모듈 A - 코스피200 ETF 11패턴 (KODEX 레버리지 122630, 숏 #11은 KODEX 인버스 114800)

### 3-1. 시점

| 단계 | 시점 | 기준 | 행동 |
|---|---|---|---|
| 판단 | 매일 20:10 | 코스피200 지수 당일 시고저종 → `daily_v3.add_bar()` → `daily_v3.judge(dep=A 평가자산)` | 보유 점검, 오늘 신호, 손절선 |
| 매수 | 신호 다음 거래일 15:21 | `judge()['signals']` 중 `dup=False`, 앞에서 `free_slots`건 | `vehicle`(레버리지/인버스) `amount` 시장가 매수 |
| 청산 | 패턴 청산 조건이 종가에 성립 → 다음 거래일 08:50 | `positions[i]['exit_signal']` | 장전 동시호가 시장가 매도 |
| 손절 | 종가가 손절선 밖 → 다음 거래일 08:50 | `positions[i]['stop_close']` (손절선 = 신호일 지수 종가 - min(5 ATR20, 10%), 신호일 값 고정) | 같은 매도 주문. 사유 '손절'. **장중 감시 없음** |
| 중복 | 보유 중인 패턴이 다시 신호 | `dup=True` | 추가 매수 없음 |

`positions[i]['sell']` 가 True 면 다음날 08:50 매도, `why` 에 '손절'/'청산'. 청산과 손절이 같은 날이면 사유는 손절.

| 4 | 5/21일선 골든크로스 + 62일선 상승 + 5일 수익 양수 | 5일선 < 21일선 |
| 5 | 62일선 상향돌파 + 62일선 상승 + RSI 40~60 | 종가 < 62일선 |
| 6 | 3일 연속 상승 + 62일선 상승 + 히스토 양수 | 종가 < 5일선 |

| 10 | 21일선 상향돌파 + 변동성 중간 + 5일 수익 음수 | 종가 < 21일선 |

## 4. 모듈 B - 월말 모멘텀 (코스피200 + 코스닥150 구성종목)

### 4-1. 규칙

| 항목 | 규칙 |
|---|---|
| 유니버스 | 코스피200 + 코스닥150 현 구성종목 (344). `universe_B.csv` 가 있으면 그 목록, 없으면 데이터 전 종목. 정기변경(6월·12월) 뒤 수동 갱신. 새로 들어온 종목은 이력 120일이 쌓여야 순위에 들어감 |
| 후보 조건 | 20일 평균 거래대금 30억 이상, 거래정지 아님 |
| 순위 | 6개월(120거래일) 수익률 내림차순 |
| 시장 스위치 | 코스피200 62일선 > 20일 전 62일선 이면 상승. 월말 판정 시 하락이면 **전량 매도, 현금** |
| 월말 교체 | 그 달 마지막 거래일 15:21: 보유 중 상위 10 밖 → 매도, 상위 10 중 미보유 → 매수 (같은 동시호가). 종목당 금액 = 모듈 평가자산 / 10 |
| 매일 매도 | 보유 종목 종가 < 자기 62일선 → 다음날 08:50 매도. 빈 자리는 다음 월말까지 현금 |
| 없음 | 손절, 목표가, 추가 매수, 장중 주문, 월중 신규 매수 |

### 4-2. 시점

| 단계 | 시점 | 기준 | 행동 |
|---|---|---|---|
| 매일 점검 | 매일 20:10 | 344종목 당일 종가·거래량 → `stock_lib.append_bars()` → `mom_lib.judge(capital=B 평가자산)` | `sells_daily` (62일선 이탈) → 내일 08:50 매도 |
| 월말 판정 | 마지막 거래일 **전날** 20:10 | `mom_lib.judge(capital, rebalance=True)` | `sells_rebalance` + `buys` 확정, 텔레그램 보고 |
| 월말 주문 | 마지막 거래일 15:21 | 위 결과 | 매도·매수 전부 장 마감 동시호가 시장가. 매도 대금은 같은 동시호가 매수에 쓴다 (증거금 범위 확인) |

### 4-3. 기대치

코스피200 종목만으로 검증한 값이 기준이다 (코스닥150 쪽은 현 구성종목 데이터의 생존편향이 커서 검증 불가, 운용에는 포함). 월말 전날 판정·월말 체결 기준 전 종목 28.7% / -31.0%, 코스피200만 22.0% / -45.1%, 리밸런싱 날을 달력에서 옮겨 20회 돌린 평균 18.7% / -35%. **연 15~20%, 낙폭 -35~-45%** 를 기대치로 둔다. 승률 49%, 연 40건 안팎, 수익은 +50% 넘는 소수 종목에서 나온다. 상세는 `개별주식_매매기법_v1.md` 9-1절, 10절.

### 4-4. 초기 상태

보유 없음, 현금 1,000만원. 첫 월말 판정은 **2026-10-30(금)**. 10/8 기준 국면 하락이라 그날도 하락이면 현금 유지, 상승으로 바뀌어 있으면 상위 10 매수.

## 7. 주문 실행

- 매수: 15:21 시장가 1회. 체결 수량이 계획의 90% 미만이면 경고 (추가 주문 없음).
- 매도: 08:50 시장가 1회. 미체결(거래정지)은 다음 거래 가능일 재시도, 상태 '매도 대기'.
- B 월말 교체: 매도와 매수를 같은 15:21 접수. 매도 대금이 당일 매수에 쓰일 수 있는지(증거금·결제) API 로 확인하고, 안 되면 매수 수량을 현금 범위로 줄인다.
- 멱등성: 주문 키 = 날짜 + 모듈 + 종목 + 사유. 상태를 먼저 기록하고 주문한다.
- 한도: 하루 매수 15건, 매도 15건. 초과 시 중지.
- 수수료·세금은 기록만.

월말 전날 보고에는 "내일 교체: 매도 [종목 수량 사유], 매수 [종목 수량 금액]"을 넣고, 월말 당일 20:20 보고에는 체결 결과를 넣는다. 장중 이벤트(체결 실패, 대사 불일치, 데이터 오류)는 즉시 별도 메시지.

## 10. 안전장치

1. dry-run: 10/13 수동 매수 기록 전까지는 모든 주문을 계획만 하고 내지 않는다. 이후 **10/24까지 dry-run** (ETF 신호 재현 확인), 10/27부터 실주문. 10/30 B 첫 교체는 실주문.
2. 데이터 날짜가 오늘이 아니거나 지수·종목 날짜가 다르면 주문 계획을 만들지 않는다.
3. API 오류 3회 재시도, 실패 시 그 작업만 건너뛰고 알림.
4. 중지 스위치: `STOP_A`, `STOP_B` 파일이 있으면 해당 모듈은 매수를 내지 않고 매도만.
5. 모듈 평가자산이 전고점 대비 -35%(A) / -45%(B)에 닿으면 그 모듈의 신규 매수를 멈추고 알린다. 재개는 수동.
6. 로그는 날짜별 파일, 텔레그램에는 요약만.

## 11. 검수 항목

1. 2026-07-24 ~ 2026-10-08 리플레이 주문이 `daily_v3.judge()` / `mom_lib.judge()` 결과와 일치한다.
2. 모듈 A 리플레이가 `roll.multi_mtm(x, P11, lev=2, cash_frac=0.2, maxpos=5, stopcap=0.10, entry_at='next_close', exit_at='open', stop_at='close')` 의 2026년 7월 이후 거래와 일치한다: 7/28 #2 신호 → 7/29 매수 → 8/14 매도 (+48%), 7/30 #7 → 7/31 매수 → 8/14 매도, 8/5 #1 → 8/6 매수 → 9/17 매도, 9/4 #10 → 9/7 매수 → 9/15 매도, 9/14 #7 → 9/15 매수 → 보유 중.
3. 모듈 B 리플레이가 `mom_lib.backtest(W, reg, exec_at='prev_judge')` 의 2026년 거래와 일치한다 (월말 전날 종가 판정, 월말 종가 체결).
4. 두 모듈 장부 합 + 미배정 현금 = 예수금이 매일 맞는다. 입금 10만원을 넣어도 모듈 자본이 안 바뀐다.
5. 휴장일, 월말이 공휴일로 당겨지는 달, 거래정지 종목, 1주 150만원 초과 종목 대체, 현금 부족이 처리된다.
6. 장중에 나가는 주문이 없다 (08:50, 15:21 이외 시각의 주문 = 버그).

## 13. 구현 착수 전 결정 사항 (v1 12절 갱신)

1. 엔진·문서는 `engine_v3.zip` (v2)을 레포 루트에 푼다. `mom_lib.judge`, `daily_B.py`, `positions_B.csv` 가 추가되었고 v1 종목 모듈은 빠졌다.
2. 기존 S2~S5 전략 코드와 v1 종목 모듈 코드는 `legacy/` 로. 스케줄러에서 뗀다.
3. 증권사 API에서 확인할 것: 코스피200 **지수** 일봉(업종코드 2001), 종목 일봉(수정주가 옵션), 장전·장마감 동시호가 참여용 일반 시장가 주문 접수 시각, 동시호가 매도 대금의 당일 매수 가용 여부. STOP 주문과 장중 현재가 조회는 **필요 없다.**
4. 자본: 모듈별 시작 자본 고정(A 2,500만, B 1,000만), 이후 각자 복리. 잔고 조회는 대사용. 유니버스는 레포 캐시(코스피200 + 코스닥150) 그대로.
